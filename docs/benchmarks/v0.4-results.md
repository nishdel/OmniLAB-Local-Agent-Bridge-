## Machine and protocol

Reference resource class: 16 GiB RAM and 6 GiB VRAM, Windows, Ollama 0.32.5.
Exact CPU/GPU identity, driver and machine inventory are withheld for privacy.
These coarse resource classes help interpret fit; timing is not portable.

Eleven frozen v0.2 task/message bodies, verified hashes, temperature 0, 8,192-token
context, 600 generated-token limit, think=false, keep_alive=0. One run per model;
no automatic retries or best-of selection. The timeout is 600 seconds per request.
Returns remain bounded JSON, normally 3,000 bytes and 1,350 for the consensus
participant exercise. A/C/R grades come from Codex's independent comparison with
the supplied source/contract. Model confidence never establishes correctness.

Wall time includes model loading and prompt evaluation. Other desktop activity
and the later model downloads overlapped some earlier benchmarks, so small timing
differences are not controlled speed rankings. No model ran concurrently with
another inference benchmark. Cold-load tests differ from a warm production model.

GPT-OSS produced no usable structured JSON in all 11 original think=false cases.

The corrected cases omit config.py from discovery, place the correct hostname:port

from triage. The retry expression and boundary descriptions are correct; that task
does not require literal numeric expectations. Grades follow the original rubric's
core requirements, rather than model confidence or a blanket JSON-success score.

## Routing decision and limits

| Cap | Enabled candidate models / roles | Production recommendation |
|---|---|---|
| Light | qwen3:4b general; phi4-mini reasoning | Cheap evidence/summary/opinion work, with Codex checking results |
| Medium | Light plus qwen2.5-coder:7b coding | Retained default; per-tool quality exclusions still apply |
| Large | Medium plus qwen3:14b-q4_K_M general/coding/reasoning | Reviewed stronger escalation, especially code analysis |
| Maximum | Large plus gpt-oss:20b general/coding/reasoning, thinking=low | Enabled experimental heavy escalation; never the default first model |

Production remains **Medium**. Its combined memory budget was raised from 12 to
16 GiB to permit the explicitly Maximum-only GPT profile; the Medium tier's own
12 GiB ceiling still applies. GPT's registry weight plus reserve is about 14.85 GiB,
and measured Ollama allocation is about 13.07 GiB, with only 3.81 GiB on GPU.
The benchmark-only budget was 18 GiB. The portable public example retains 12 GiB
and the three small role examples; it does not import this machine's preferences.
Memory is tight on this PC and these are configured budgets, not OS reservations.

Qwen3.5 9B and Coder14 remain installed but disabled experiments. DeepSeek remains
disabled with its v0.3 history. No existing enabled model was removed or deleted.
Coder7 is retained for inexpensive first-pass review; its high rejection rate means
it is not a dependable general coding worker. The coarse analyze_code gate excludes
it, so that tool hands back to Codex at Medium and begins with Qwen3 14B at Large.
At Maximum its next stronger eligible candidate is GPT-OSS. Other simple calls
start with Qwen4, Coder7 or Phi; moderate/stronger hints may skip weaker candidates.
Maximum does not override the two-attempt budget, so a third model is not automatically
run after two attempts. GPT is useful when it is within the remaining attempt budget.

A separate **real stdio MCP follow-up** used an independently corrected Qwen3 14B
request and selected GPT-OSS with reason previous_attempt_failed at Maximum.
It completed in 70.76 seconds: 1,156 input and 229 output tokens, 2,765 supplied
bytes and a 1,270-byte final routing envelope (54.1% local compression). The test cap
was isolated; production stayed Medium. The result included correct bare/tagged/port
pairs but an incomplete optional pytest snippet, so Codex reported **corrected**.
The provider filled a 240-character schema field; the bridge did not clip it.
Structurally valid JSON and truncated=false cannot certify complete executable code.
No code snippet was executed or applied automatically.

The new benchmark has 44 calls: 11 each for Qwen3.5 and Coder14, plus two 11-case
GPT protocols. Add one routed GPT follow-up. Thus new-model calls are 11 / 11 / 23,
including 11 strict-protocol failures. Independent clean-install verification calls
are recorded separately. Each paired suite has one second-opinion/consensus-participant
exercise; real multi-participant consensus was also exercised by the setup smoke.
Completed metadata and explicit feedback were copied into the local dashboard store
without changing its cap or duplicating existing request IDs. Historical strict
protocol failures remain visible; the public comparison separates them from low mode.

The router selects the smallest eligible configured capability strength for the
requested role. Explicit tier assignments use observed usefulness, specialization,
memory and latency; they do not bypass memory/latency limits. Generic profiles can
provide optional per-tool reviewed reliability without changing code. Local reviewed
data takes precedence. Unreviewed profiles are clearly marked, not represented as
validated. Three reviewed cases trigger the current 25% acceptance / 50% maximum
rejection gate; the tiny sample size is a remaining weakness.

Input/attempt limits remain 10,000 characters and two local attempts. The delegation
policy recommends local analysis of at most eight files, medium minimum confidence,
and 25% minimum compression for sufficiently large contexts. Selected-file reading
has its own 20-file hard bound plus the input budget. Low confidence, invalid/truncated output,
contradictory evidence, unsupported requirements and failed attempts can escalate
within the selected cap. Ambiguous, complex multi-file, architectural and high-risk
work belongs with Codex under the project policy; complex routing hints force a handoff.
Caller-supplied scope/risk hints and Codex review remain necessary: the bridge cannot
prove semantic complexity or correctness from schema/size alone. Agreement is not
proof and no autonomous agent loop was added.
The coarse per-tool gate currently blocks Coder7 analyze_code after its three
reviewed cases; Medium can therefore hand this back immediately. Better task-level
evidence is needed before expanding that model's routing.
